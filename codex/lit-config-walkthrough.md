# MLIR lit Config Walkthrough: Build → Source → Python

This annotated guide explains, from first principles, how MLIR’s tests are configured with lit. It walks through the three key configuration layers and shows how settings and features propagate so tests can run reliably:

- Build site config: `build/tools/mlir/test/lit.site.cfg.py`
- Source config: `mlir/test/lit.cfg.py`
- Python subtree overrides: `mlir/test/python/lit.local.cfg`

---

## Big Picture: How Configuration Flows

```
lit discovers a test under mlir/test/...
  → loads build/tools/mlir/test/lit.site.cfg.py (generated)
      • sets build-specific paths, tool dirs, feature toggles
      • then calls: lit_config.load_config(..., mlir/test/lit.cfg.py)
  → executes mlir/test/lit.cfg.py (source-controlled)
      • defines test format, file suffixes, exec roots
      • injects PATH/PYTHONPATH and tool substitutions (mlir-opt, FileCheck, etc.)
      • computes/exports available features used by REQUIRES/UNSUPPORTED
  → applies lit.local.cfg in subtrees when present (e.g., mlir/test/python)
      • local environment tweaks, gating, excludes
```

Key takeaway: the site config contributes build-specific values (absolute paths, toggles), then hands off to the source config which implements most behavior. Directory-local configs refine behavior only within their subtree.

## 1) Build Site Config (Generated)

File: [`build/tools/mlir/test/lit.site.cfg.py`](build/tools/mlir/test/lit.site.cfg.py)

- Generated by CMake for your build; captures paths and feature toggles discovered/configured at build time.

How it propagates
- All variables on `config` (paths, toggles, host info) are visible to `mlir/test/lit.cfg.py`, guiding tool discovery, environment wiring, and available features.

## 2) Source Config (Project‑Controlled)

File: [`mlir/test/lit.cfg.py`](mlir/test/lit.cfg.py)

Why it exists
- Defines how MLIR tests run: test formats, file types, execution roots, tool substitutions, and environment.
- Computes feature flags used by test annotations.

Suite basics
- Name and format:
  - [`mlir/test/lit.cfg.py:20`](mlir/test/lit.cfg.py#L20) suite name = "MLIR"
  - [`mlir/test/lit.cfg.py:32-33`](mlir/test/lit.cfg.py#L32-L33) ShTest (runs `RUN:` lines; internal shell by default)
- What files are considered tests:
  - [`mlir/test/lit.cfg.py:35-48`](mlir/test/lit.cfg.py#L35-L48) test file suffixes (`.mlir`, `.py`, `.ll`, ...)
- Where tests run:
  - [`mlir/test/lit.cfg.py:50-54`](mlir/test/lit.cfg.py#L50-L54) `test_source_root` and `test_exec_root` (build mirror under `build/tools/mlir/test`)

Core substitutions and environment
- Basic substitutions available in `RUN:` lines:
  - [`mlir/test/lit.cfg.py:56-61`](mlir/test/lit.cfg.py#L56-L61) `%PATH%`, `%shlibext`, `%llvm_src_root`, `%mlir_src_root`, `%host_cc`, `%host_cxx`
- Tools and runtime libraries on PATH / as substitutions:
  - PATH injection: [`mlir/test/lit.cfg.py:185-187`](mlir/test/lit.cfg.py#L185-L187)
  - Tool list + runtime libs (expand as `%mlir_runner_utils`, etc.): [`mlir/test/lit.cfg.py:189-215`](mlir/test/lit.cfg.py#L189-L215), [`mlir/test/lit.cfg.py:220-246`](mlir/test/lit.cfg.py#L220-L246)
  - Optional tools and helper substitutions: [`mlir/test/lit.cfg.py:247-264`](mlir/test/lit.cfg.py#L247-L264)
  - Apply substitutions so `RUN:` can just say `mlir-opt` or `%mlir_runner_utils`: [`mlir/test/lit.cfg.py:323`](mlir/test/lit.cfg.py#L323)
- Default FileCheck behavior for MLIR tests:
  - [`mlir/test/lit.cfg.py:326-329`](mlir/test/lit.cfg.py#L326-L329) sets `FILECHECK_OPTS="-enable-var-scope --allow-unused-prefixes=false"`

Python support
- `%PYTHON` substitution and ASAN handling:
  - [`mlir/test/lit.cfg.py:266-301`](mlir/test/lit.cfg.py#L266-L301)
- Python module path so `from mlir.ir import *` works in tests:
  - [`mlir/test/lit.cfg.py:335-344`](mlir/test/lit.cfg.py#L335-L344) appends MLIR wheels from your build to `PYTHONPATH`

Feature computation (REQUIRES/UNSUPPORTED)
- Assertions, host capabilities, GPU availability, Python version, etc.:
  - [`mlir/test/lit.cfg.py:346-385`](mlir/test/lit.cfg.py#L346-L385)
- Many of these depend on booleans set by the site config (e.g., `config.run_nvptx_tests`, `config.enable_cuda_runner`), so changing your build flags alters which tests run.

How it propagates
- Everything set here (PATH, substitutions, PYTHONPATH, FILECHECK_OPTS, features) directly affects how lit interprets and runs `RUN:` lines in test files.

## 3) Python Subtree Overrides (Local)

File: [`mlir/test/python/lit.local.cfg`](mlir/test/python/lit.local.cfg)

Why it exists
- Adds Python‑specific behavior for the `mlir/test/python` subtree without affecting other tests.

What it changes
- Disables ASAN leak detection for Python tests (commonly noisy):
  - [`mlir/test/python/lit.local.cfg:1`](mlir/test/python/lit.local.cfg#L1)
- Skips the entire subtree if Python bindings weren’t built (respects site config’s `config.enable_bindings_python`):
  - [`mlir/test/python/lit.local.cfg:2-3`](mlir/test/python/lit.local.cfg#L2-L3)
- Excludes generated DSL tablegen file from discovery:
  - [`mlir/test/python/lit.local.cfg:4`](mlir/test/python/lit.local.cfg#L4)

How it propagates
- Applies only under `mlir/test/python/`. Other directories continue to use the global settings from `mlir/test/lit.cfg.py` and the build site config.

## Putting It Together: From Test Line To Execution

Example 1: FileCheck test (`.mlir`)
- Test contains: `// RUN: mlir-opt %s -pass | FileCheck %s`
- Site config provides absolute paths and shared‑lib extension.
- Source config adds `mlir-opt` to PATH and `FILECHECK_OPTS`.
- lit expands `%s` to the test file, resolves tools, runs the pipeline, and verifies output.

Example 2: Python test (`.py`)
- Test contains: `# RUN: %PYTHON %s | FileCheck %s`
- Site config provides `config.python_executable` and flags like `enable_bindings_python`.
- Source config wires `%PYTHON` substitution and appends built MLIR packages to `PYTHONPATH`.
- Python subtree local config disables leak detection and can mark the subtree unsupported if bindings weren’t built.
