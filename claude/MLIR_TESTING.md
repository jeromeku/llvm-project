## What is lit?

**lit** (LLVM Integrated Tester) is a Python-based testing framework used across the LLVM project, including MLIR. It provides a standardized way to discover, configure, and execute tests.

### How lit Works

```
┌─────────────────────────────────────────────────────────────┐
│                       lit Test Discovery                     │
│                                                              │
│  1. Start from test root directory                          │
│  2. Load lit.site.cfg.py (generated by CMake)               │
│  3. Load lit.cfg.py (source-controlled config)              │
│  4. Discover all test files matching configured suffixes    │
│  5. For each test:                                           │
│     • Parse RUN: directives from test file                  │
│     • Apply substitutions (tools, paths, variables)         │
│     • Execute commands in sequence                          │
│     • Capture output and match with CHECK: directives       │
└─────────────────────────────────────────────────────────────┘
```

### Key Concepts

1. **RUN Directives**: Lines starting with `// RUN:` or `# RUN:` define shell commands to execute
2. **CHECK Directives**: Lines with `// CHECK:` or `# CHECK:` define expected output patterns
3. **Substitutions**: Placeholders like `%s`, `%PYTHON`, `mlir-opt` that lit replaces with actual paths
4. **Features**: Capabilities that can enable/disable tests (e.g., `asserts`, `host-supports-nvptx`)
5. **Test Format**: Usually `ShTest` which executes shell-like commands

### MLIR lit.cfg.py

Located at: [`mlir/test/lit.cfg.py`](mlir/test/lit.cfg.py)

This source-controlled file defines how tests run:

```python

config.test_format = lit.formats.ShTest(execute_external=not use_lit_shell)

# Recognized test file extensions

# Tool substitutions (key for running tests!)
tools = [
    "mlir-opt",
    "mlir-translate",
    "FileCheck",
    # ... many more

llvm_config.add_tool_substitutions(tools, tool_dirs)

# Python path setup (for Python tests)
if config.enable_bindings_python:
    llvm_config.with_environment(
        "PYTHONPATH",
        [
            os.path.join(config.mlir_obj_root, "python_packages", "mlir_core"),
            os.path.join(config.mlir_obj_root, "python_packages", "mlir_test"),
        ],
        append_path=True,
    )
```

## Running Individual Tests Manually

This is the most important section! Here's how to run tests without lit.

### Understanding Test Structure

Every test file contains special directives that lit parses. Here's an example:

**Test file**: [`mlir/test/Dialect/Affine/loop-coalescing.mlir`](mlir/test/Dialect/Affine/loop-coalescing.mlir)

```mlir
// RUN: mlir-opt -split-input-file -allow-unregistered-dialect -affine-loop-coalescing --cse --mlir-print-local-scope %s | FileCheck %s

// CHECK-LABEL: @one_3d_nest
func.func @one_3d_nest() {
  // CHECK-DAG: %[[orig_lb:.*]] = arith.constant 0
  %c0 = arith.constant 0 : index
  // ... rest of test
}
```

**Directives explained**:
- `// RUN:` - Command to execute (with substitutions)
- `%s` - Substituted with the test file path
- `| FileCheck %s` - Pipe output to FileCheck which verifies against CHECK directives
- `// CHECK-LABEL:` - Match this pattern in output
- `// CHECK-DAG:` - Match these patterns in any order
- `// CHECK:` - Match this pattern in sequence

### Core MLIR Tests (FileCheck-based)

#### Example 1: Affine Loop Coalescing Test

**Test location**: [`mlir/test/Dialect/Affine/loop-coalescing.mlir:1`](mlir/test/Dialect/Affine/loop-coalescing.mlir#L1)

**RUN directive**:
```bash
// RUN: mlir-opt -split-input-file -allow-unregistered-dialect -affine-loop-coalescing --cse --mlir-print-local-scope %s | FileCheck %s
```

**What lit provides**:
1. **Tool paths**: `mlir-opt` → `/home/jeromeku/llvm-project/build/bin/mlir-opt`
2. **Substitutions**: `%s` → full path to test file
3. **PATH environment**: Includes `build/bin/` directory
4. **Working directory**: `build/tools/mlir/test/` (test execution root)

# Method 2: Just see the transformed output (no checking)

  -split-input-file \
  -allow-unregistered-dialect \

#### Common Python Test Pitfalls

When running Python tests manually, you might encounter:

**Error 1**: `ModuleNotFoundError: No module named 'mlir'`
- **Cause**: PYTHONPATH not set
- **Fix**: Add `PYTHONPATH=./tools/mlir/python_packages/mlir_core:./tools/mlir/python_packages/mlir_test`

**Error 2**: `ImportError: cannot import name 'ir' from 'mlir._mlir_libs._mlir'`
- **Cause**: C++ extension modules not found or incompatible
- **Fix**: Ensure you're in the build directory and libraries were compiled successfully
- **Debug**: Check if `./tools/mlir/python_packages/mlir_core/mlir/_mlir_libs/_mlir.*.so` exists

**Error 3**: `OSError: libMLIR*.so: cannot open shared object file`
- **Cause**: LD_LIBRARY_PATH doesn't include MLIR libraries
- **Fix**: Add `LD_LIBRARY_PATH=./lib:$LD_LIBRARY_PATH`

## Test Types

MLIR uses several types of tests:

### 1. FileCheck Tests (.mlir, .ll, .td)

**Purpose**: Verify compiler transformations produce expected output

**Structure**:
```mlir
// RUN: mlir-opt %s -pass-name | FileCheck %s

// CHECK-LABEL: func @test_name
func.func @test_name(%arg0: i32) -> i32 {
  // CHECK: %[[V0:.*]] = arith.addi
  %0 = arith.addi %arg0, %arg0 : i32
  // CHECK: return %[[V0]]
  return %0 : i32
}
```

**CHECK variants**:
- `CHECK:` - Must match in order
- `CHECK-NEXT:` - Must match on the very next line
- `CHECK-SAME:` - Must match on the same line as previous CHECK
- `CHECK-DAG:` - Must match, but order doesn't matter within DAG group
- `CHECK-LABEL:` - Defines a new scope for checking
- `CHECK-NOT:` - Must NOT match

**How to run manually**: Extract RUN line, substitute `%s` with file path, execute

### 2. Python Tests (.py)

**Purpose**: Test Python API bindings

**Structure**:
```python
# RUN: %PYTHON %s | FileCheck %s

from mlir.ir import *

def test_something():
    # CHECK: Expected output here
    print("Expected output here")

test_something()
```

**How to run manually**: Set PYTHONPATH, run with Python, optionally pipe to FileCheck

### 3. C++ Unit Tests (GTest)

**Purpose**: Test internal C++ APIs and data structures

**Structure**:
```cpp
TEST(AffineMapTest, inferMapFromAffineExprs) {
  MLIRContext context;
  // ... test implementation
  EXPECT_EQ(expectedValue, actualValue);
}
```

**How to run manually**: Execute the compiled test binary directly with GTest flags

### 4. Integration Tests

**Purpose**: End-to-end testing with execution

**Example**: Tests that compile MLIR → LLVM → native code → run → verify output

**Structure**:
```mlir
// RUN: mlir-opt %s -pass-pipeline='...' | \
// RUN: mlir-cpu-runner -e main -entry-point-result=void | \
// RUN: FileCheck %s

// CHECK: Expected runtime output
```

**Special requirements**:
- May need runtime libraries (`mlir_runner_utils`, `mlir_c_runner_utils`)
- May require specific hardware (GPU, AVX, etc.)
- Set via `LD_LIBRARY_PATH` or embedded RPATH

## Debugging Tips

### 1. See Exact Commands lit Runs

```bash
python ../llvm/utils/lit/lit.py -v -a tools/mlir/test/YOUR_TEST.mlir
```

Copy the executed commands from output and run directly.

### 2. Check Test Discovery

```bash
python ../llvm/utils/lit/lit.py --show-tests tools/mlir/test/
```

Ensure your test is discovered.

### 3. Verify Configuration

```bash
python ../llvm/utils/lit/lit.py --show-suites tools/mlir/test/
```

Check features, substitutions, and paths.

### 4. Run Without FileCheck

Remove the `| FileCheck ...` part to see raw output:

```bash
./bin/mlir-opt -affine-loop-coalescing ../mlir/test/Dialect/Affine/loop-coalescing.mlir
```

### 5. Python Import Debugging

```bash
PYTHONPATH=./tools/mlir/python_packages/mlir_core python -c "import mlir.ir; print(mlir.ir.__file__)"
```

Should print path to `ir.py` in your build.

### 6. Check Shared Library Dependencies

```bash
ldd ./tools/mlir/python_packages/mlir_core/mlir/_mlir_libs/_mlir.cpython-312-x86_64-linux-gnu.so
```

Verify all MLIR libraries resolve.

## Summary

**To run tests individually**:

1. **Identify test type** (FileCheck, Python, or Unit test)
2. **Find the RUN directive** (or executable for unit tests)
3. **Substitute variables**:
   - `%s` → test file path
   - `%PYTHON` → Python executable
   - Tool names → `build/bin/TOOL`
4. **Set environment**:
   - Python: `PYTHONPATH=build/tools/mlir/python_packages/mlir_core:...`
   - Runtime: `LD_LIBRARY_PATH=build/lib` (if needed)
5. **Execute from build directory**

**You don't need lit** for individual test execution - it's just a convenience wrapper that automates discovery, configuration, and execution.

**Reference files**:
- Main test config: [`mlir/test/lit.cfg.py`](mlir/test/lit.cfg.py)
- Build-specific config: [`build/tools/mlir/test/lit.site.cfg.py`](build/tools/mlir/test/lit.site.cfg.py)
- Unit test config: [`build/tools/mlir/test/Unit/lit.site.cfg.py`](build/tools/mlir/test/Unit/lit.site.cfg.py)
